# System Architecture

Project position: **AI Native Multi-Agent Market Runtime**.

This repository is a dry-run-first multi-agent runtime for market research, signal review, simulated execution, risk snapshots, and learning feedback. It is not positioned as an automatic profit system, high-frequency arbitrage platform, or institutional quant fund stack.

## Orchestrator

`orchestrator.py` coordinates a single scan through `main.py --mode once`. The orchestrator owns sequencing, runtime file bootstrap, signal freshness checks, signal consolidation, risk snapshot generation, dry-run execution gating, and best-effort execution of agents.

The orchestrator intentionally remains simple: each stage is a script call or local method, and failures in individual agents are logged without automatically expanding the system.

## Layered Structure

| Layer | Components |
|---|---|
| Collection | US stocks collector, Agent A, market-specific collectors |
| Research and signal generation | Agent B, Agent K v2, Agent D/E/F/H/J, OKX funding |
| Strategy and allocation | Regime Detector, Strategy Manager, Capital Adapter |

| Execution | buy executor, Agent P, sell executor |
| Learning | Agent G, `learning_report.json`, `learning_knowledge_base.json` |
| Operations | monitor scripts, metrics collection, Agent I |

## Data Flow

1. Collectors and research agents write runtime data under `data/`.
2. The orchestrator consolidates fresh signals into `data/signals.json`.
3. The risk engine writes `data/risk_snapshot.json`.
4. Agent M reads `signals.json`, `risk_snapshot.json`, and `learning_knowledge_base.json`, then writes approval results.
5. Executors read approved signals and write `execution_results.json`.
6. Agent G reads dry-run synthetic trades or closed trade history, then writes learning artifacts.
7. Later review cycles can inject `learning_knowledge_base.json` into Agent M prompts.

## Risk Layer

The risk layer is intentionally lightweight. It provides a runtime snapshot and prompt context, not an institutional portfolio risk framework. Current risk protection comes from:

- signal freshness checks before review and execution
- Agent M review and cache behavior
- fail-closed behavior when review cannot safely approve
- dry-run execution enforcement
- `risk_snapshot.json` generated by `risk/risk_engine.py`

## Learning Bridge

Agent G is the learning bridge. In dry-run, it can use synthetic trades marked as `dry_run=true` and `synthetic=true`. If the LLM is unavailable, Agent G uses deterministic fallback statistics based on closed trades and rejection distributions.

The bridge refreshes:

- `data/learning_report.json`
- `data/learning_knowledge_base.json`

The current bridge is heuristic and file-based. It does not update model weights, train embeddings, or provide online learning in the institutional sense.

## Dry-Run Safety

The current frozen stage is dry-run only. Safety controls include:

- `EXECUTOR_DRY_RUN=1`
- mock trader path support through `PM_TRADER_PATH=/tmp/mock_pm_trader.sh`
- `execution_results.json` expected `success=0`
- skipped execution output when signals are missing, stale, or invalid
- monitor script restored to `TOTAL_CYCLES=8`

Real trading validation has not been completed.
